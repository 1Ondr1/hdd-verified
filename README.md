# HDD Verified

[![CI](https://github.com/1Ondr1/hdd-verified/actions/workflows/ci.yml/badge.svg)](https://github.com/1Ondr1/hdd-verified/actions/workflows/ci.yml)

Каталог игр с оценкой того, как они ведут себя на разных жёстких дисках.
Аналог ProtonDB, но про скорость диска.

## Идея

Игра требует места и умеет стримить ассеты; диск на 5400 об/мин с SMR
превращает это в минуты загрузок и фризы. Пользовательский вопрос звучит
не «какая у меня модель», а «пойдёт ли у меня» — поэтому на странице есть
**общая оценка** и разбивка по классам накопителей.

## Как это устроено

- **Профили накопителей** — 3 класса жёстких дисков, которые реально
  различают опыт: HDD 7200 CMR, HDD 5400 CMR, HDD SMR. Статистика
  считается по профилям, а не по тысячам моделей: два диска разных
  производителей с одинаковыми характеристиками попадают в одну группу.
- **Накопитель пользователя** — полное название (`Seagate Barracuda
  ST2000DM008`) и три характеристики: объём, обороты, технология записи.
  Название нужно только для показа в профиле и отчётах, а класс
  определяется оборотами и записью (SMR важнее оборотов). Справочника
  моделей, автодополнения и заявок нет — всё вводится вручную.
- **Отчёты** — авторизованный пользователь ставит вердикт для игры на своём
  накопителе: «играбельно», «с оговорками», «неиграбельно», плюс фризы,
  скорость загрузки до меню и комментарий. Одна оценка на игру: смена или
  удаление диска перезаписывает её, а не добавляет вторую. Название и
  характеристики диска сохраняются в отчёте как снимок, поэтому история
  остаётся понятной даже после удаления накопителя.
- **Вход только через Steam** — паролей и регистрации на сайте нет. Steam
  OpenID подтверждает владение аккаунтом, а сайт получает только публичные
  данные: SteamID64, ник и аватар. Одноразовый `state` привязывает callback
  к сессии и не даёт повторно использовать чужой ответ. Авторизация нужна
  как защита от спама.
- **Фильтр отчётов** — на карточке игры можно оставить только отчёты с
  нужными оборотами и технологией записи. Кнопка «Моя конфигурация»
  подставляет характеристики основного диска пользователя, чтобы не
  выбирать их вручную. Фильтрация идёт по снимкам в отчётах, а не по
  текущему профилю. Объём диска в фильтре не участвует: на поведение игры
  он не влияет.
- **Общая оценка** — сглаженное байесовское среднее по всем отчётам.
  Отчёты без указания диска весят меньше, скрытые модератором не влияют.
  Показывается только при достаточном числе отчётов.
- **Размер игры** — требование магазина показывается отдельно, а рядом —
  медиана свежих пользовательских замеров из отчётов. Замер считается
  актуальным 365 дней: патчи и обновления быстро меняют размер, поэтому
  старые данные не участвуют в расчёте, но и не удаляются.
- **Требования магазинов** — объём и упоминание SSD подтягиваются из
  `appdetails` Steam и контентного API Epic. Это ориентир, а не точный
  размер: фактическое место зависит от версии, DLC и патчей.
- **Два магазина** — игры берутся из Steam и Epic Games Store. Steam в
  приоритете: если игра есть в обоих, показывается и хранится steam-запись.
  Epic ищется через публичный GraphQL (`searchStore`/`catalogOffer`), а
  требования к диску — через `store-content.ak.epicgames.com`.
- **Язык интерфейса** — русский, английский и украинский, переключатель
  в шапке. Данные магазинов хранятся в базовом английском варианте (регион
  US), а русская и украинская версии — в отдельных полях.
  Обложки Steam — широкий арт 616×353 со страницы магазина: адрес
  читается из самой страницы (`store_capsule`), потому что Steam отдаёт
  его по хешированному пути, который меняется вместе с обложкой. Для
  русского и украинского хранятся отдельные локализованные версии
  (`cover_url_ru`, `cover_url_uk`).
- **Названия** — в базе хранятся `title` (английский оригинал),
  `title_ru` и `title_uk`, а интерфейс показывает `display_title` по
  текущему языку с откатом на английский.
- **Поиск** — только игры: DLC, саундтреки и демо отсекаются фильтрами
  Steam `category1=998` и Epic `category: "games"`. Обложки берутся с CDN
  магазинов в крупном размере.

## Запуск

```powershell
uv sync
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver
```

Переменные окружения — в `.env` (образец: `.env.example`). Без
`DJANGO_SECRET_KEY` работает только при `DJANGO_DEBUG=1`.

Вход на сайт — только через Steam OpenID, паролей нет. Ключ
`STEAM_API_KEY` (Steam Web API) не обязателен: без него вход работает,
но ник и аватар не подтягиваются, и в интерфейсе остаётся техническое имя
`steam_<SteamID64>`. Админка `/admin/` по-прежнему входит по паролю.

На хостинге за HTTPS-прокси включите `DJANGO_TRUST_PROXY_SSL_HEADER=1`:
иначе Django будет считать запрос http-шным, и Steam вернёт пользователя
на `http://`-адрес.

Перевод комментариев к отчётам работает через DeepL: добавьте ключ
`DEEPL_API_KEY` в `.env` (бесплатный тариф — ключ заканчивается на `:fx`).
Без ключа кнопка «Перевести» просто не показывается, остальной сайт
работает как обычно. Переводы сохраняются в базе, поэтому каждый
комментарий переводится один раз на язык; если автор изменит текст,
сохранённый перевод сбрасывается и запрашивается заново.

Создать администратора:

```powershell
.\.venv\Scripts\python.exe manage.py createsuperuser
```

## Полезные команды

```powershell
# добавить игру из Steam по AppID
.\.venv\Scripts\python.exe manage.py import_game 1091500

# добавить игру из Epic по namespace:id
.\.venv\Scripts\python.exe manage.py import_game epic:c4763f236d08423eb47b4c3008779c84:a7364ebfa54147f1b90f78a81c8093f7

# обновить данные уже добавленной игры
.\.venv\Scripts\python.exe manage.py import_game 1091500 --refresh

# перечитать обложки Steam со страниц магазина (все игры или один AppID)
.\.venv\Scripts\python.exe manage.py refresh_covers

# тесты
.\.venv\Scripts\python.exe manage.py test
```

## Прод

Боевой режим включается переменными окружения, а не правкой кода:

```env
DJANGO_DEBUG=0
DJANGO_SECRET_KEY=<длинная случайная строка>
DJANGO_ALLOWED_HOSTS=hdd-verified.onrender.com
DJANGO_CSRF_TRUSTED_ORIGINS=https://hdd-verified.onrender.com
DJANGO_TRUST_PROXY_SSL_HEADER=1
DATABASE_URL=postgresql://user:password@host/db
```

- **База.** При заполненном `DATABASE_URL` используется PostgreSQL
  (`psycopg`), иначе — локальный `db.sqlite3`. Для Neon/Render TLS
  включается сам (`sslmode=require`).
- **Статика.** WhiteNoise отдаёт файлы из процесса, отдельный nginx не
  нужен. Перед запуском: `python manage.py collectstatic --noinput`.
- **HTTPS.** При `DJANGO_DEBUG=0` включены редирект на HTTPS, защищённые
  cookie и HSTS на год. Исключение — `/health/`: его опрашивает хостинг.
- **Здоровье.** `GET /health/` возвращает `{"status": "ok"}` (200), если
  база отвечает, и 503, если нет.
- **Логи.** Пишутся в stdout одной строкой (`DJANGO_LOG_LEVEL`), их видно
  в панели хостинга.

Деплой на Render описан в `render.yaml` (free-план, регион Frankfurt,
база — Neon). Полная пошаговая инструкция появится перед публикацией.

## Структура

```
render.yaml        blueprint Render: сборка, gunicorn, /health/
config/            настройки, маршруты, загрузка .env, /health/
games/
  models.py        Game, DriveProfile, UserDrive, Report, SteamProfile
  i18n.py          словарь переводов RU/EN без GNU gettext
  templatetags/
    i18n_extras.py тег {% t "ключ" %}
  services/
    steam.py       Steam Store API, разбор требований
    steam_auth.py  вход через Steam OpenID и публичный профиль
    epic.py        Epic Games Store GraphQL
    catalog.py     результат поиска и сравнение названий
    search.py      объединение выдачи Steam и Epic
    games.py       получение игры в каталог
    drives.py      определение класса по оборотам и технологии записи
    stats.py       агрегация отчётов
    reports.py     сохранение отчётов
  views.py         страницы, Steam-вход и JSON-поиск игр
  forms.py         накопители и отчёты
  admin.py         классы накопителей, каталог и модерация отчётов
```
